# Calibrate

사용자가 한 번의 요청으로 세 설정의 후보를 비교하게 합니다. 후보 생성은 읽기 전용이며, 선택 뒤에만 원래 과업의 검증과 적용을 이어갑니다.

## 입력 판별

- 새 과업이면 세 후보를 생성합니다.
- `A`, `B`, `C` 중 하나만 주어지고 현재 세션에 대기 중인 비교가 있으면 선택 처리로 봅니다.
- 선택 이유가 함께 있으면 사용자 확정 선호로 보존합니다. 이유가 없어도 선택을 받습니다.

## 후보 생성

1. 이 파일의 디렉터리를 기준으로 `scripts/calibrate.py`를 찾습니다.
2. 현재 작업 디렉터리와 사용자 요청을 그대로 넘겨 다음을 실행합니다.

   ```text
   python3 <skill-dir>/scripts/calibrate.py start --cwd <cwd> --task <request>
   ```

   요청이 길거나 셸 인용이 불안하면 현재 작업용 임시 파일에 원문을 쓰고 `--task-file <path>`를 사용합니다. 사용자가 모델이나 추론 수준을 지정했을 때만 해당 옵션을 명시합니다. 그 외에는 스크립트가 현재 세션과 Codex 설정에서 같은 값을 해석합니다.
3. 스크립트가 출력한 `A`, `B`, `C`를 내용 수정이나 사전 평가 없이 그대로 제시합니다. 프로필 매핑, 추천, 점수, 차이 설명은 선택 전까지 숨깁니다.
4. 세 후보 중 하나라도 실패하면 비교를 제시하지 않습니다. 실패한 프로필과 재시도에 필요한 최소 정보만 보고합니다.

`clean`은 공급자 기본 동작에 공통 읽기 전용 봉투만 적용합니다. `core`는 여기에 최소 사실성 계약을 더합니다. 두 프로필은 현재 계정 인증만 연결한 임시 `CODEX_HOME`에서 실행합니다. `full`은 현재 사용자 AGENTS, 로컬 스킬, 설정을 유지합니다. 세 실행은 같은 모델, 추론 수준, 작업 디렉터리, 요청을 사용합니다. 훅, 알림, MCP, 외부 앱, 플러그인, 웹 검색, 하위 에이전트는 후보 생성에 필요하지 않으므로 세 실행 모두에서 끕니다.

## 선택 처리

1. 다음 명령으로 가장 최근 비교를 공개합니다.

   ```text
   python3 <skill-dir>/scripts/calibrate.py reveal <A|B|C> --json
   ```

   사용자가 이유를 말했다면 `--reason <text>`로 함께 넘깁니다.
2. JSON을 사용자에게 그대로 노출하지 않고 다음을 보고합니다.
   - 선택한 후보와 실제 프로필
   - 사용자가 직접 말한 선호
   - 후보의 정확한 대목에서 추정한 선호 가설
   - 사실, 테스트, 출처로 확인한 유효성
3. 사용자가 말하지 않은 이유는 `추정`으로 표시합니다. 직관 선택에 설명을 강요하지 않습니다.
4. 선택한 후보가 유효성 검증에 실패하면 채택하지 않습니다. 실패 근거를 보여주고 다른 후보 선택 또는 보정 중 무엇이 필요한지 제안합니다.
5. 원래 요청이 변경을 승인했다면 선택한 방향으로만 구현하고 검증합니다. 외부 게시, 데이터 삭제, 비가역 행동은 별도 승인을 받습니다.

## 불변 조건

- 후보끼리 내용을 자동 합성하지 않습니다. 사용자가 지정한 대목만 선택안에 가져옵니다.
- A/B/C 선택으로 사실의 참과 거짓을 결정하지 않습니다. 직관은 조사할 방향을, 증거는 채택 가능성을 결정합니다.
- 후보 생성 중 파일이나 외부 상태를 바꾸지 않습니다. 변경 과업은 제안안을 비교한 뒤 선택한 하나만 원래 세션에서 실행합니다.
- 한 번의 선택을 AGENTS, 스킬, 메모리의 새 규칙으로 자동 승격하지 않습니다. 서로 다른 실제 과업에서 같은 선호가 반복되면 규칙 후보로만 제안합니다.
- 격리 플래그를 적용할 수 없으면 실제 `clean`이라고 부르지 않고 비교를 중단합니다.

## 완료 기준

새 과업은 매핑이 숨겨진 세 후보와 선택 방법을 전달하면 후보 단계가 끝납니다. 선택 과업은 프로필 공개, 선호 분리, 유효성 검증, 요청된 최종 적용까지 마쳐야 끝납니다.
