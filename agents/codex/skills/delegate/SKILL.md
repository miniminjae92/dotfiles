# Delegate

목표 달성 품질을 유지하면서 메인 스레드의 잡음과 관측 가능한 총 사용량을 줄입니다. 위임 자체를 목표로 삼지 않습니다.

## 판정

요청을 실행 위치와 논리 역할로 분리합니다. 메인 스레드는 `planner` 역할을 맡아 요구 해석, 분해, 연속 판단, 사용자 상태, 최종 통합을 유지합니다.

다음 조건을 모두 만족하는 단위만 자식에게 위임합니다.

- 입력이 완결돼 있어 자식이 숨은 맥락을 추측하지 않습니다.
- 완료 조건을 산출물이나 명령으로 검증할 수 있습니다.
- 실패와 변경을 되돌릴 수 있으며 외부 상태를 바꾸지 않습니다.
- 인수인계보다 절약할 탐색과 출력 컨텍스트가 큽니다.
- 병렬 작업이면 파일 소유권과 의존성이 겹치지 않습니다.

하나라도 만족하지 않거나 메인이 곧바로 끝낼 수 있는 T0 작업이면 메인 스레드가 수행합니다.

## 역할

- `planner`: 요구 해석, 아키텍처, 강결합 구현, 사용자 상태, 비가역 행동, 최종 결론입니다. 메인 스레드가 수행합니다.
- `clerk`: 닫힌 입력의 스키마 기반 추출과 정규화입니다. Codex 어댑터가 검증되기 전까지 메인 스레드가 수행합니다.
- `worker`: 범위가 좁은 구현, 테스트, 재현 가능한 조사입니다. `agent_type=worker`로 위임합니다.
- `reviewer`: 보안, 데이터 손실, 높은 영향의 변경을 문맥 없이 독립 검토합니다. 필요한 경우에만 `agent_type=reviewer`로 위임합니다.

역할과 모델 연결은 `~/.dotfiles/agents/routing.json`과 custom agent TOML이 정합니다. 스킬은 모델명을 선택하거나 spawn 시점에 override하지 않습니다.

Codex 또는 agent TOML이 바뀐 뒤에는 새 프로세스에서 binding smoke test를 통과한 역할만 활성화합니다. spawn과 구조화된 응답을 모두 확인하고 실행 기록에 남깁니다. 일반 호출마다 smoke test를 반복하지 않습니다.

## 위임 계약

자식에게 `fork_turns=none`과 함께 다음 계약을 완결된 문장으로 전달합니다.

```text
목적:
제공 입력:
허용된 탐색 범위:
허용된 변경 파일:
금지된 외부 변경:
완료 조건:
검증 명령:
결과 형식: 결론, 근거, 불확실성, 변경 파일, 검증
실패 형식: 차단 원인, 확인한 범위, 다음 최소 행동
```

파일을 편집하는 worker에는 서로 겹치지 않는 파일만 배정합니다. reviewer는 읽기 전용으로 사용합니다.

## 실행과 통합

1. 위임 단위를 하나의 역할과 하나의 계약으로 고정합니다.
2. worker 또는 reviewer를 `fork_turns=none`으로 생성합니다.
3. 역할이 unavailable이면 기본 agent나 부모 모델로 대체하지 않고 메인에서 수행합니다. 결과에 `adapter_unavailable`을 남깁니다.
4. 자식 결과를 원래 완료 조건에 대응하고 실제 산출물과 검증 명령을 확인합니다.
5. 누락, 충돌, 불확실성만 메인에서 보완하고 최종 결론을 냅니다.

같은 계약의 반복 재시도 대신 역할을 재분류합니다. worker에서 planner로 올린 실패는 `agent-os-friction --origin agent "escalation: worker→planner | <작업> | <이유>"`로 기록합니다. 상위 역할에서 과도하게 쉬웠던 반복 업무는 하향 후보로 남깁니다.

## 비용 경계

- 부모 컨텍스트 감소를 총토큰 절감으로 부르지 않습니다.
- 비용을 비교할 때는 부모와 모든 자식의 관측 토큰을 합산합니다.
- 자식 사용량을 관측할 수 없으면 비용 판정을 유보합니다.
- 자식은 원시 로그 대신 요청한 결과 형식으로만 반환합니다.
