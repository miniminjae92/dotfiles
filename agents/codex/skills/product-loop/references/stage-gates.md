# Product Loop stage gates

현재 단계 절만 읽는다. 각 게이트는 문서 존재가 아니라 판단에 필요한 증거가 있는지를 확인한다.

## 1. 문제 발견

- 기록: 관찰된 행동·증상, 영향을 받는 사용자와 맥락, 증거 출처, 아직 모르는 것
- 게이트: 해결책 표현 없이 관찰 가능한 문제 후보와 조사할 핵심 불확실성이 구분됨

## 2. 사용자 조사

- 기록: 조사 질문, 참여자 또는 자기관찰 조건, 원문·행동 증거, 반복 패턴과 반증
- 개인 도구: 사용자가 유일한 사용자라면 기억에 의존한 선호 대신 실제 과업 수행과 마찰을 관찰함
- 게이트: UX 문제를 지지하거나 기각할 행동 증거가 있고 표본 한계를 명시함

## 3. UX 문제 정의

- 기록: `[사용자]는 [맥락]에서 [목표]를 이루려 하지만 [마찰] 때문에 [영향]을 겪는다`, 성공 신호, 비목표
- 게이트: 해결책 없이 하나의 핵심 문제와 성공 판단 기준이 합의됨

## 4. Grill

- `grilling`으로 가정, 예외, 우선순위, 비용, 실패와 복구를 한 질문씩 검증함
- 게이트: 열린 결정이 없거나, 미결정 항목마다 소유자와 결정 시점이 있음

## 5. PRD

- 기록: 문제, 목표·비목표, 사용자 이야기, 요구사항, 성공 지표, 제약, 수용 기준
- 게이트: 모든 요구사항이 앞선 증거에 연결되고 검증 가능한 수용 기준을 가짐

## 6. UX flow

- 기록: 진입점, happy path, 빈 상태, 오류, 취소, 복구, 종료 상태를 포함한 상태 전이
- 게이트: 모든 사용자 이야기와 예외가 어느 흐름에 속하는지 추적 가능함

## 7. Wireframe

- 기록: 정보 위계와 주요 상호작용을 보여주는 저충실도 화면, 각 화면이 답하는 질문
- 게이트: 시각 장식 없이 과업 순서와 필요한 정보가 검토 가능함

## 8. Prototype test

- 기록: 검증 질문, 과업 시나리오, 관찰 기록, 성공·실패·놀라움, 바뀐 결정
- 게이트: 프로토타입을 만든 사실이 아니라 실제 사용 관찰로 핵심 위험을 판정함

## 9. UI design

- 기록: 확정된 화면, 상태별 표현, 반응형 동작, 접근성, 레퍼런스와 선택 근거
- 게이트: UX flow의 모든 상태가 시각적으로 정의되고 구현자가 추측할 핵심 결정이 없음

## 10. Issues

- 기록: 한 컨텍스트에서 끝나는 검증 가능한 수직 조각, 의존 관계, 수용 기준
- 게이트: 각 이슈가 독립적으로 시연 가능하고 현재 frontier가 식별됨
- 외부 트래커 게시 전에 사용자 승인을 받음

## 11. 구현

- 기록: 완료 이슈, 코드 결정, 테스트, 알려진 차이
- 게이트: 승인된 수용 기준을 구현했고 관련 자동 검증이 통과함

## 12. Functional QA

- 기록: PRD 수용 기준별 실제 결과, 환경, 실패 재현과 심각도
- 게이트: 모든 기준이 passed 또는 승인된 예외로 판정됨

## 13. Design QA

- 기록: 확정 디자인 대비 시각·상호작용·반응형·접근성 차이와 증거 이미지
- 게이트: 모든 차이가 수정되거나 의도적 편차로 승인됨

## 14. 출시

- 기록: 대상 환경, 버전·커밋, 마이그레이션, 복구 절차, 출시 결과
- 게이트: 사용자가 외부 변경을 승인했고 실제 대상에서 건강 상태와 복구 가능성을 확인함

## 15. 측정

- 기록: 기준값, 출시 후 값, 관찰 기간, 정성 피드백, 교란 요인
- 게이트: 계측 계획이 아니라 실제 결과로 성공 지표를 판정함

## 16. UX 개선 가설

- 기록: `[증거] 때문에 [변경]하면 [행동]이 바뀌어 [지표]가 [방향]으로 움직일 것이다`
- 게이트: 측정 결과에서 나온 검증 가능한 가설 하나와 다음 조사 방법이 정해짐
