# reasoning-reviewer 활용 가이드

이 스킬은 내 생각을 하나 이상 가져가 가장 큰 빈틈과 다음 검증을 받는 데 가장 잘 맞는다. 처음부터 답을 만들어 달라고 하기보다, 내가 어디까지 생각했고 무엇이 불확실한지 보여주면 짧고 구체적인 검토를 받을 수 있다.

## 가장 짧은 호출

시간이 없을 때는 현재 생각 한 줄만 붙인다.

```text
$reasoning-reviewer 지금 내 생각은 "..."입니다.
가장 큰 빈틈 하나와 지금 할 가장 작은 검증만 알려줘.
```

## 코딩 전 5분

모든 칸을 억지로 채울 필요는 없다. 현재 판단에 필요한 것만 한두 문장으로 적는다.

```text
$reasoning-reviewer

코딩 전 5분 검토입니다.

What
현재 확인된 현상이나 문제:

Expected
원래 기대한 상태:

Evidence
그렇게 판단한 코드, 로그, 테스트, 관찰:

Why
현재 원인 가설과 그 근거:

Unknown
판단에 중요하지만 아직 모르는 것:

Next
내가 생각한 가장 작은 다음 검증:

확인된 사실, 가설, Unknown을 구분해줘.
가장 큰 빈틈 하나를 먼저 지적하고, Next가 가설을 판별할 수 있는지 검토해줘.
답이나 구현은 대신하지 마.
```

Goal이 선택을 바꾸는 문제라면 맨 위에 원하는 상태를 한 줄 추가한다. 검토를 받은 뒤에는 Next를 실행하고 결과를 다시 전달한다.

```text
$reasoning-reviewer 방금 검증 결과는 "..."였습니다.
어떤 가설이 강화되거나 약해졌는지와 다음 검증 하나만 봐줘.
```

## 상황별 프롬프트

### 문제 정의

```text
$reasoning-reviewer
내 문제 정의가 현상, 문제, 원인 가설, 해결책을 섞고 있는지 검토해줘.

현재 정의: ...
근거: ...

가장 큰 혼동 하나와 더 정확한 What을 제안해줘.
```

### 원인 추론과 디버깅

```text
$reasoning-reviewer
확인된 현상: ...
내 원인 가설: ...
현재 Evidence: ...

근거보다 앞서간 추론을 찾아줘.
이 가설을 다른 원인과 구분할 증거 하나와 가장 작은 확인 방법을 제안해줘.
```

### A와 B 사이의 결정

```text
$reasoning-reviewer
Goal: ...
대안 A: ...
대안 B: ...
현재 중요하다고 생각한 Criteria: ...

빠진 핵심 Criteria가 있는지 검토하고, Goal에 연결된 Trade-off를 보여줘.
내가 판단할 수 있게 조건부 결론으로 답해줘.
```

추천까지 원하면 마지막 문장을 다음처럼 바꾼다.

```text
너라면 무엇을 선택할지 먼저 말하고, 그 선택을 바꿀 조건도 알려줘.
```

### 문서, Issue, PR

```text
$reasoning-reviewer
독자: ...
읽은 사람이 이해하거나 결정해야 하는 것: ...
현재 초안: ...

근거 없는 주장, 결론으로 점프한 부분, 빠진 완료 조건이나 Verify만 찾아줘.
문서 전체를 다시 쓰지는 마.
```

### 학습

```text
$reasoning-reviewer
제가 이해한 내용은 다음과 같습니다: ...
막힌 부분은 ...입니다.

현재 설명에서 가장 큰 오해나 빈칸 하나를 찾아줘.
이 판단에 필요한 개념만 설명한 뒤 제가 다시 설명할 질문 하나를 해줘.
```

## 잘 쓰는 기준

- 내 결론보다 관찰한 사실을 먼저 준다.
- 원인에는 현재 근거를 함께 붙인다. 근거가 없으면 없다고 쓴다.
- "전부 검토해줘"보다 지금 중요한 빈틈 하나를 요청한다.
- Next에는 행동뿐 아니라 어떤 결과가 나오면 가설을 유지하거나 버릴지도 적는다.
- 직접 추천, 수정, 구현까지 원하면 그 범위를 명시한다.

## 피할 프롬프트

```text
이거 어떻게 해야 해?
```

현재 생각이 없어 사고 검토보다 답안 생성으로 흐르기 쉽다. 대신 현재 관찰, 추측, 막힌 지점 중 하나를 붙인다.

```text
가능한 원인을 전부 알려줘.
```

가능성만 늘어나기 쉽다. 대신 가장 가능성 높은 가설 몇 개와 서로 구분할 Evidence를 요청한다.

```text
이 문제를 해결해줘.
```

이미 명확한 실행을 맡길 목적이라면 reasoning-reviewer가 아니라 원하는 결과와 검증 조건을 직접 요청한다. 검토 뒤 실행까지 맡기려면 "검토 후 직접 수정해줘"처럼 범위를 분명히 쓴다.

## 활용 루프

```text
내 생각 작성
→ reasoning-reviewer 검토
→ 가장 작은 검증 실행
→ 결과 공유
→ 가설이나 결정 갱신
```

한 번의 사용은 다음 검증 하나가 정해지면 끝이다. 큰 문제라면 이 짧은 루프를 반복한다.
