# 문제 해결 기록

## Purpose

문제를 발견한 근거부터 해결 가설, 선택, 실행, 관찰, 배움까지 남겨 문제를 어떻게 풀었고 무엇을 얻었는지 설명한다.

문제를 해결하기 전에 잘못된 문제 정의나 근거 없는 가설을 발견하고, 해결한 뒤에는 과정과 결과를 과제 제출이나 팀 공유에 사용할 수 있게 한다.

## Content

다음 내용을 포함한다.

- 해결하려는 문제
- 문제가 실제로 있다고 판단한 근거
- 해결 여부를 판정할 완료 기준
- 예상하는 변화와 이를 만들 기술적 가설
- 검토한 대안과 선택 이유
- 실행 계획
- 실제 실행 내용
- 실행 전후의 관찰
- 문제 해결에서 얻은 배움
- 배움을 바탕으로 이어갈 다음 행동

초안에서는 `문제`부터 `실행 계획`까지만 작성한다. `실행`, `관찰`, `배움`, `다음 행동`은 실제 작업에서 근거가 생길 때 작성한다.

## Structure

```markdown
# <문제 해결 제목>

## 문제

## 근거

## 완료 기준

## 가설

## 대안과 선택

## 실행 계획

## 실행

## 관찰

## 배움

## 다음 행동
```

내용이 아직 없는 `실행`, `관찰`, `배움`, `다음 행동`은 초안에서 생략할 수 있다. 대안이 실질적으로 하나뿐이라면 선택하지 않은 대안을 억지로 만들지 않고 그 이유를 적는다.

## Lifecycle

### 초기 작성

- 이전 대화, 기존 문서, 저장된 컨텍스트가 없다고 가정하고 시작한다.
- 사용자가 처음 문제를 인식한 장면과 당시 생각을 사용자의 말로 먼저 듣는다.
- 한 번에 하나의 판단만 다룬다.
- 사용자가 말한 관찰과 자료로 검증한 사실을 구분한다.
- 문제의 의미와 완료 기준은 사용자가 결정한다.
- 가설은 실행 후 맞았는지 틀렸는지 판단할 수 있게 작성한다.
- 의미 있는 선택지가 있을 때만 대안과 차이를 제시하고, 사용자가 선택한 이유를 남긴다.
- 실행 계획은 현재 보이는 범위까지만 작성한다.
- 사용자가 선택하거나 수정하지 않은 에이전트의 제안은 확정 내용으로 넣지 않는다.
- 근거가 부족하면 해결책을 바로 실행하지 않고 문제의 존재나 범위를 확인하는 일을 계획에 둔다.

### 계획 검토와 칸반 연결

- 문제 해결 기록 초안을 먼저 완성하고 사용자가 실행 계획을 검토한다.
- 초안과 계획이 합의되기 전에는 칸반 카드를 만들지 않는다.
- 사용자가 실행 계획에서 한 칸반 카드로 수행할 범위를 결정한다.
- 에이전트는 카드 단위를 제안할 수 있지만 대신 확정하지 않는다.
- 카드가 완료되면 문제 해결 기록에 의미 있는 결론을 반영할 수 있어야 한다.

### 실행과 갱신

- 실제로 수행한 내용만 `실행`에 적는다.
- 실행 전후에 확인한 변화와 예상과의 차이를 `관찰`에 적는다.
- 가설이 틀리거나 새로운 사실이 나오면 가설, 대안과 선택, 실행 계획을 현재 이해에 맞게 갱신한다.
- 결과를 이해하는 데 필요한 실패와 방향 전환은 남기되, 상세 명령과 사소한 시행착오는 별도 작업 기록에 둔다.
- 칸반 카드가 끝날 때마다 기록과 계획을 갱신하고, 다음 칸반 단위는 사용자가 다시 결정한다.

### 종료

- 완료 기준을 근거로 충족 여부를 판정한다.
- 문제를 풀면서 달라진 이해를 `배움`에 적는다.
- 이어서 수행할 구체적인 일이 있으면 `다음 행동`에 적는다.
- 후속 행동이 없다면 `없음`이라고 적고 종료할 수 있다.
- 처음 읽는 사람이 문제, 판단, 실행, 결과를 다른 문서 없이 이해할 수 있는지 확인한다.

## Evaluation

### 초기 작성 점검

- [ ] 문제가 한 문장으로 명확한가?
- [ ] 문제의 존재나 영향을 뒷받침하는 근거가 있는가?
- [ ] 완료 여부를 판정할 기준이 있는가?
- [ ] 가설의 예상 결과를 실행 후 확인할 수 있는가?
- [ ] 선택한 대안과 이유가 사용자의 판단을 반영하는가?
- [ ] 실행 계획이 문제, 근거, 가설에서 자연스럽게 이어지는가?
- [ ] 칸반 카드가 초안과 계획 합의 전에 만들어지지 않았는가?

### 실행과 갱신 점검

- [ ] 계획과 실제 실행이 구분되어 있는가?
- [ ] 관찰이 예상이나 해석이 아니라 확인한 변화에 근거하는가?
- [ ] 틀린 가설과 의미 있는 실패를 숨기지 않았는가?
- [ ] 새로운 사실이 가설과 계획에 반영됐는가?
- [ ] 다음 칸반 단위를 사용자가 결정했는가?

### 종료 점검

- [ ] 완료 기준의 충족 여부를 근거로 판단했는가?
- [ ] 실행과 관찰에서 배움이 자연스럽게 도출되는가?
- [ ] 다음 행동이 구체적이거나 `없음`으로 명시되어 있는가?
- [ ] 처음 읽는 사람이 문제 해결의 흐름과 결과를 이해할 수 있는가?
