# 문제 해결 기록 Workflow

## Purpose

아무 컨텍스트가 없는 상태에서 사용자의 생각을 꺼내 문제 해결 기록의 초안을 만들고, 사용자가 선택한 단위를 칸반 카드로 실행하며, 실행과 관찰에서 얻은 내용으로 기록을 갱신한다.

## 호출

사용자는 다음처럼 문제 해결의 시작만 알리면 된다.

```text
문제 해결 기록: <지금 떠오르는 문제>
```

문제가 아직 문장으로 정리되지 않았다면 다음처럼 호출해도 된다.

```text
문제가 있는 것 같은데 같이 정리하자.
```

호출 직후에는 기존 대화, 기존 문서, 저장된 컨텍스트를 전제로 삼지 않는다. 사용자가 명시적으로 가져오라고 한 자료만 입력으로 사용한다.

## 1. 문제와 근거 꺼내기

목표는 문서를 바로 채우는 것이 아니라 사용자가 실제로 해결하려는 문제를 드러내는 것이다.

1. 사용자가 문제를 처음 인식한 장면과 당시 생각을 듣는다.
2. 한 번에 판단 하나만 다룬다.
3. 사용자의 답을 짧게 되짚고, 의미가 달라질 수 있는 모호함만 질문한다.
4. 사용자가 모르는 부분에는 선택지와 각 선택이 만드는 차이를 제안한다.
5. 사용자가 선택하거나 고친 내용만 결정으로 취급한다.

다음 항목을 질문 목록처럼 억지로 소진하지 않는다. 사용자의 말에서 이미 확인된 것은 되묻지 않는다.

- 어떤 장면에서 무엇을 문제라고 느꼈는가
- 누구에게 어떤 불편이나 손실이 생기는가
- 문제가 실제로 있다고 생각한 근거는 무엇인가
- 어떤 상태가 되면 해결됐다고 판단할 수 있는가

근거가 없거나 약하다는 사실이 드러나면 실패로 보지 않는다. 해결책 구현보다 문제의 존재와 범위를 확인하는 일을 먼저 계획한다.

## 2. 가설과 계획 만들기

문제, 근거, 완료 기준이 정해지면 예상하는 변화와 기술적 가설을 세운다. 의미 있는 대안이 있으면 선택지별 결과와 대가를 제안하고 사용자가 선택하게 한다.

선택한 가설을 확인하기 위한 실행 계획을 작성한다. 이 단계에서는 저장소 조사나 실제 구현을 먼저 수행하지 않는다. 확인이 필요한 내용은 실행 계획에 넣는다.

## 3. 초안 제안

에이전트는 충분한 내용이 모이면 문서에 쓰기 전에 다음을 구분해 제안한다.

- 사용자가 결정한 내용
- 자료로 확인된 사실
- 에이전트가 문장으로 다듬은 부분
- 아직 결정이 필요한 부분

사용자가 승인하거나 수정하면 문제 해결 기록 초안을 작성한다. 미채택 제안과 대화 과정은 본문에 넣지 않는다.

승인된 초안은 출력 설정에 따라 저장한다. 사용자가 이번 기록의 다른 저장 위치를 명시하면 그 위치를 우선한다. 새 기록과 같은 이름의 파일이 이미 있으면 자동으로 덮어쓰지 않는다.

초안은 다음 상태를 만족하면 충분하다.

- `문제`, `근거`, `완료 기준`, `가설`, `대안과 선택`, `실행 계획`이 현재 아는 범위에서 작성되어 있다.
- 확인된 사실, 사용자의 판단, 아직 검증하지 않은 가설이 구분되어 있다.
- 빈칸을 채우기 위해 근거 없는 내용을 만들지 않았다.

## 4. 계획 검토와 칸반 단위 결정

사용자는 문제 해결 기록 초안에 담긴 실행 계획을 먼저 검토하고 수정한다. 계획이 현재 문제를 해결하는 흐름으로 충분한지 합의하기 전에는 칸반 카드를 만들지 않는다.

계획이 정해지면 사용자가 어느 범위를 칸반 카드 한 장으로 수행할지 결정한다. 에이전트는 가능한 작업 단위와 차이를 제안할 수 있지만 카드의 크기를 대신 확정하지 않는다.

칸반 단위 후보는 다음 조건으로 검토한다.

- 결과가 하나다.
- 완료 여부를 판정할 수 있다.
- 별도로 담당, 우선순위 지정, 보류, 검토할 수 있다.
- 너무 잘게 나뉘어 팀이 결과보다 절차를 관리하게 만들지 않는다.
- 완료되면 문제 해결 기록에 의미 있는 결론을 반영할 수 있다.

사용자가 단위를 선택하면 해당 범위로 첫 칸반 카드를 만든다. 카드에는 문제 해결 기록 링크를 연결한다. 상세한 조사 과정이 이후에도 근거로 필요할 때만 작업 기록을 별도로 만들고 카드에는 링크만 둔다.

## 5. 실행과 갱신

칸반 카드의 작업을 수행하면서 문제 해결 기록을 갱신한다.

1. 실제로 수행한 내용을 `실행`에 적는다.
2. 실행 전후의 변화와 예상과 다른 결과를 `관찰`에 적는다.
3. 새로운 사실로 가설이나 계획이 달라지면 해당 항목을 갱신한다.
4. 의미 있는 실패와 방향 전환은 남기고 사소한 작업 로그는 분리한다.
5. 카드가 끝나면 완료 기준과 전체 실행 계획을 다시 확인한다.
6. 다음 칸반 단위는 사용자가 결정한다.

## 6. 배움과 다음 행동

문제가 끝났거나 한 번의 해결 주기가 끝나면 실행과 관찰을 바탕으로 `배움`을 작성한다. 이어서 할 구체적인 일이 있으면 `다음 행동`에 적고, 없으면 `없음`으로 종료한다.

다음 행동이 새로운 문제라면 기존 기록의 범위를 늘리지 않고 새 문제 해결 기록으로 시작한다.

## 진행 원칙

- 컨텍스트를 자동으로 끌어오지 않는다.
- 승인된 결과물은 출력 설정에 지정된 기본 위치에 저장한다.
- 에이전트가 사용자의 문제 정의나 완료 기준을 대신 결정하지 않는다.
- 문제 해결 기록 초안과 계획을 합의하기 전에 실제 조사, 구현, 칸반 카드 작성을 시작하지 않는다.
- 칸반 카드의 작업 단위는 사용자가 결정한다.
- 문서 작성을 위한 질문 목록을 기계적으로 소진하지 않는다.
- 답을 이미 얻은 질문은 다시 묻지 않는다.
- 바로 작업할 수 있을 정도가 되면 더 완벽한 문장을 위해 시작을 늦추지 않는다.
- 모호함, 선택지 충돌, 큰 비용이나 되돌리기 어려운 결정이 있을 때만 깊게 파고든다.
