# meeting-notes — 전사본을 팀 회의록으로

목적: **매번 좋아지는 회의록 파이프라인.** 단발 요약이 아니다.
같은 팀이 매주 회의하면 ASR은 같은 도메인 용어를 매주 틀린다. 그걸 사전에 축적해
스크립트가 결정적으로 고치고, 모델은 판단에만 쓴다.

핵심 원칙:

1. **원본 불변.** 전사 txt는 아카이브에 사본으로 보존한다. 원본 파일은 절대 수정하지 않는다.
2. **결정적인 건 스크립트가, 판단은 모델이.** 용어 치환, 메타 추출, 발화 병합은 `prep.py`가 한다.
   "로션이 사실 노션인가?"를 매번 모델이 재추측하게 두지 않는다.
3. **학습 루프.** 실행 끝에 새 오인식을 사전에 추가 제안한다. 다음 회의는 그만큼 덜 틀린다.

## 프로젝트 데이터 위치

```
~/.obsidian/yggdrasil/3-stash/meeting-notes/<프로젝트>/
  _config.json      # 소스 폴더, Notion 게시 대상
  _glossary.md      # ASR 교정 사전 (표준어: 오인식1, 오인식2)
  _roster.md        # 참석자 힌트 (매핑표 아님)
  YYYY-MM-DD.md     # 생성된 회의록
  raw/YYYY-MM-DD.txt  # 원본 전사 사본
```

`ARCHIVE_ROOT`로 재정의 가능. 프로젝트가 여럿이면 전사 파일명 접두사로 고른다.
처음 보는 프로젝트면 디렉터리·`_glossary.md`·`_config.json`을 만들지 물어본다.

## ① 입력 해석

인자로 전사 파일 경로를 받는다. 없으면 `_config.json`의 `source_dir`에서 최신 후보를 찾아
**확인받고** 진행한다. 추측으로 아무 파일이나 열지 않는다.

```bash
ls -t ~/Downloads/google-downloads/*_[0-9][0-9][0-9][0-9][0-9][0-9].txt | head -5
```

이미 `<아카이브>/YYYY-MM-DD.md`가 있으면 **덮어쓰기 전에 물어본다.**

## ② 전처리 — 모델 호출 0

```bash
SKILL=~/.claude/skills/meeting-notes
ARCH=~/.obsidian/yggdrasil/3-stash/meeting-notes/<프로젝트>

python3 "$SKILL/scripts/prep.py" <전사.txt> --meta-only          # 날짜·참석자 수 확인
python3 "$SKILL/scripts/prep.py" <전사.txt> \
  --glossary "$ARCH/_glossary.md" --out /tmp/prepped-<날짜>.md
```

stderr 리포트를 **반드시 읽는다.**

- `[치환]` — 무엇이 몇 건 고쳐졌는지. 사전이 잘 듣고 있는지 여기서 보인다.
- `[검토]` — 정상 단어와 겹쳐 자동 치환하지 않은 것들(`오류`↔`보류` 등).
  **해당 위치를 직접 찾아 문맥으로 판단한다.** 이걸 건너뛰면 회의록이 틀린다.

원본 사본을 아카이브에 남긴다 (원본은 그대로 둔다):

```bash
mkdir -p "$ARCH/raw" && cp <전사.txt> "$ARCH/raw/<YYYY-MM-DD>.txt"
```

## ③ 회의록 작성 — 여기서만 모델을 쓴다

`/tmp/prepped-<날짜>.md`와 `references/template.md`, `_roster.md`를 읽고 작성한다.
템플릿의 **작성 규칙 7개를 그대로 지킨다.** 특히:

- 팀 공유 문서다 — 도구 티가 나는 상투구 없이, 사람이 정리한 글처럼 읽혀야 한다.
- 전사에 없는 담당자, 기한을 지어내지 않는다. 모르면 `확인 필요`.
- 미결을 결론으로 승격하지 않는다.
- 화자 번호를 실명으로 단정하지 않는다 — Clova 번호는 회의마다 바뀐다.
- 녹음 세팅, 잡담은 버린다.

## ④ 지난 회의 대조

아카이브에서 직전 회의록(현재보다 앞선 날짜 중 최신)을 찾는다.
`_`로 시작하는 설정 파일은 글롭에서 자동으로 빠진다.

```bash
CUR=<이번 회의 YYYY-MM-DD>
PREV=$(/bin/ls "$ARCH"/[0-9]*.md 2>/dev/null | xargs -n1 basename | sed 's/\.md$//' \
       | sort | awk -v c="$CUR" '$1 < c' | tail -1)
echo "직전 회의록: ${PREV:-없음}"
```

있으면 그 회의록의 `## 액션 아이템` 표를 읽어 이번 회의록 앞쪽에
`## 지난 액션 아이템 상태` 표를 넣는다. 각 항목을 `완료 / 진행 중 / 이번 회의에서 언급 없음`으로
분류하고 **근거 발화를 한 줄로 남긴다.**

**언급이 없으면 `언급 없음`이다. 완료로 올리지 않는다.** 직전 회의록이 없으면 이 단계를 건너뛴다.

완성본을 `$ARCH/<YYYY-MM-DD>.md`에 쓴다.

## ⑤ Notion 게시

`_config.json`의 `notion.target`이 있으면 그리로, 없으면 이번 한 번 확정한다.

**게시 전 부호 관문.** 팀에게 나가는 글이므로 여기서 한 번 더 막는다.
PostToolUse 훅은 "레거시 줄이면 두십시오"라 통과시킨 것도 있는데, 게시물에는 남으면 안 된다.

```bash
ko-style "$ARCH/<YYYY-MM-DD>.md"
```

`[dash]`, `[slash]`가 남아 있으면 대체표대로 고친 뒤 게시한다.

**게시 전에 문법 명세를 먼저 읽는다 — 추측 금지.** 표, 체크박스, 토글이 표준 마크다운과 다르다.

```
mcp__notion__notion-fetch  id: notion://docs/enhanced-markdown-spec
```

`target`이 비어 있으면:

1. `notion-fetch`로 대상 페이지를 열어 구조를 파악한다(데이터베이스인가, 일반 페이지인가).
2. 게시 방식을 **사용자에게 제안하고 승인받는다** — DB 행 / 하위 페이지 / 본문 append.
3. 확정된 `target`(page_id 또는 data_source_id)과 `mode`를 `_config.json`에 기록한다.
   다음 회의부터는 묻지 않는다.

팀 게시처가 따로 없는 회의라면 기본 제안은 에이전트 허브의 **공유 산출물** 페이지
(`3b37265b311281a7bdc4d66d44d371a3`) 하위 페이지다. 어디에 게시하든 그 페이지의
게시 기준을 따른다 — 사람이 쓴 글로 읽혀야 한다.

게시 후 URL을 보고한다.

**팀 공유 페이지다. 승인 없이 덮어쓰거나 기존 내용을 지우지 않는다.**
기존 페이지 수정이 필요하면 무엇을 바꿀지 먼저 말하고 승인받는다.

접근이 안 되면(404 등) 여기서 멈추고 로컬 md 경로를 보고한다. ①~④는 이미 끝나 있다.

## ⑥ 사전 갱신 제안 — 다음 회의를 위한 투자

이번 전사에서 **새로 만난** ASR 오인식을 찾아 제안한다. 이미 `_glossary.md`에 있는 건 뺀다.

```
사전에 추가할까요?
  칸반: 간판(2건)      "간판 보드에 올려주세요" ← 문맥상 칸반
  배포: 배표(1건)
```

**승인받은 것만 `_glossary.md`에 추가한다. 자동 추가 금지** — 오탐이 쌓이면 교정이 오염되고,
그때부터는 스크립트가 멀쩡한 문장을 망가뜨리기 시작한다.

정상 단어와 겹치는 후보는 `?` 접두사로 넣어 검토 전용으로 만든다.

## 마무리 보고

- 로컬 회의록 경로 + Notion URL(게시했다면)
- `[치환]` 총 건수와 `[검토]` 항목을 어떻게 판단했는지
- 회의록에 남긴 `확인 필요` 항목 — 사용자가 직접 채워야 할 것들
- 사전 추가 제안

## 하지 않는 것

- **폴더 감시 자동 실행 없음.** 팀 공유 문서라 검수 없이 올라가면 안 된다.
- 전사 원본 수정, 삭제 없음. 아카이브에 복사만.
- `term` 스킬과 겹치지 않는다 — `_glossary.md`는 ASR 문자열 교정용이지
  유비쿼터스 랭귀지 정본이 아니다. 정본은 repo `CONTEXT.md`/`docs/adr/`다.
